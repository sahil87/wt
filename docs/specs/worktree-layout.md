# Worktree Layout

Where worktrees live on disk, how they are named, and how the worktree
directory relates to its branch.

## Filesystem layout

Worktrees are created as **siblings** of the main repository, grouped under a
single per-repo directory:

```
<parent>/
├── <repo>/                  # main repo (clone or working directory)
└── <repo>.worktrees/        # all linked worktrees for this repo
    ├── swift-fox/
    ├── jolly-otter/
    └── crimson-heron/
```

The location is derived in `internal/worktree/context.go`:

```
WorktreesDir = filepath.Join(filepath.Dir(repoRoot), repoName + ".worktrees")
```

The main repo root itself is resolved by stripping `/.git` from
`git rev-parse --git-common-dir` — the same value regardless of whether the
command is run from the main repo or from a linked worktree.

## Naming convention

| Field | Value |
|-------|-------|
| **Pattern** | `{adjective}-{noun}` |
| **Example** | `swift-fox`, `jolly-otter` |
| **Generated by** | `wt create` (via `internal/worktree/names.go`) |
| **Override** | `--name <name>` (`-n`; deprecated alias `--worktree-name`) |

`GenerateRandomName()` picks one entry from each of two curated word lists
(`adjectives` and `nouns`) and joins them with a single hyphen. The default
combinatorial space is large enough that collisions are rare.

`GenerateUniqueName(worktreesDir, maxRetries)` retries up to `maxRetries=10`
times to find a name that does not collide with an existing directory under
`<repo>.worktrees/`. After exhaustion, `wt create` exits with
`ExitRetryExhausted` and a message pointing the user at
`<repo>.worktrees/`.

When the user passes `--name` (or the deprecated `--worktree-name`), no random
name is generated and no retry happens — the name is used as-is and an existing
directory at that name is an error (or, with `--reuse`, signals that the
existing worktree should be returned instead of created).

### Temp worktrees

`wt create --temp <ref>` worktrees are always named with the `tmp-` prefix
(`TempNamePrefix` in `internal/worktree/names.go`) so they are visibly
disposable in every listing:

| Invocation | Directory |
|------------|-----------|
| `--temp <ref>` | `tmp-<adjective>-<noun>` (via `GenerateUniqueNameWithPrefix`; collision checked on the prefixed name) |
| `--temp <ref> --name foo` | `tmp-foo` |
| `--temp <ref> --name tmp-foo` | `tmp-foo` (the prefix is never doubled) |

`wt list` classifies a worktree as temp when it is detached, not the main
worktree, and its directory name starts with `tmp-` (`IsTempWorktree`) — a pure
check on data the single porcelain listing already returns. A detached worktree
without the prefix, or a `tmp-*` worktree on a branch, is not temp.

## Branch ↔ worktree relationship

The branch checked out in a worktree is **independent** of the worktree
directory name. Three illustrative cases:

1. **Exploratory / new-branch worktree** (no positional, or a positional
   naming a *new* branch): a new branch is created — named after the worktree
   for the bare case (`swift-fox` worktree on `swift-fox` branch), or the
   positional name otherwise. The two strings happen to match in the bare case,
   but they are independent values — renaming the branch later does not move the
   directory. A positional naming an *already-existing* branch is rejected (see
   [cli-surface.md](cli-surface.md) § `wt create`) — use `--checkout` for that.
   Branches `wt create` creates carry their recorded base in git config
   (`branch.<name>.wt-base` / `wt-base-sha`), surfaced as `base` / `base_sha` in
   `wt list --json`; `--checkout` / `--pr` branches and `--temp` worktrees carry none.
2. **Worktree for an existing branch** (`--checkout <branch>`): the worktree
   directory still gets a random or user-supplied name, while the branch stays
   whatever the user passed (`<repo>.worktrees/swift-fox/` checked out on branch
   `feature/oauth`). When deriving a default worktree name from the `--checkout`
   branch, `DeriveWorktreeName` takes the last path segment after `/` and
   replaces non-alphanumeric characters (except `-` and `_`) with `-` — so
   branch `feature/oauth-pkce` yields suggestion `oauth-pkce`.
3. **Temp / detached worktree** (`--temp <ref>`): HEAD is detached at the
   resolved commit — **no branch exists** and no git config is written. There
   is nothing for `wt delete` to clean up: branch handling (including
   `--branch true`) is skipped for any detached worktree.

`wt delete --branch auto` collapses the first two cases by deleting the
branch only when it matches the worktree name — the typical exploratory case.
For the second case (worktree name and branch differ), `auto` keeps the
branch.
